# Claude Code + cc-connect Setup

This guide explains how to use [cc-connect](https://github.com/chenhg5/cc-connect) to bridge Claude Code CLI to this companion app.

## Why cc-connect?

When using Claude Code CLI as your AI backend, you get:

- **MCP tools** — Claude Code can use any MCP server (memory, calendar, browser automation, etc.)
- **Extended thinking** — thinking blocks are generated by the CLI and streamed to the frontend
- **Full Claude Code features** — hooks, CLAUDE.md, tool use, file editing, all work normally

Without cc-connect, you face a trade-off:

| Approach | MCP Tools | Thinking Blocks | Notes |
|----------|-----------|-----------------|-------|
| server.js calls OpenAI API | No | No | Default mode. `/chat/completions` doesn't return thinking. |
| server.js calls Anthropic API | No | Yes | Requires code changes. No MCP tools since CLI isn't involved. |
| tmux pipe to server.js | Yes | No | CLI handles messages but thinking isn't passed to frontend. |
| **cc-connect bridge** | **Yes** | **Yes** | **CLI has full features. cc-connect streams everything to the app.** |

## Architecture

```
┌─────────────┐     ┌──────────────┐     ┌──────────────────┐
│  Your phone  │────▶│  Companion   │◀────│   cc-connect     │
│  (browser)   │◀────│  App (8787)  │     │   (bridge)       │
└─────────────┘     └──────────────┘     └───────┬──────────┘
                                                  │
                                          ┌───────▼──────────┐
                                          │  Claude Code CLI  │
                                          │  (with MCP tools) │
                                          └──────────────────┘
```

- **Companion App** serves the web UI and stores messages.
- **cc-connect** bridges Claude Code CLI output to the app's API endpoints.
- **Claude Code CLI** is the AI backend — it processes messages, uses MCP tools, and generates responses with thinking.

## Setup

### Prerequisites

- Node.js 18+
- A Claude Pro/Max/Team subscription (for Claude Code CLI)
- Claude Code CLI installed (`npm install -g @anthropic-ai/claude-code`)

### Step 1: Start the companion app

```bash
git clone https://github.com/tjing9430/cc-companion-app.git
cd cc-companion-app
cp .env.example .env
npm start
```

The app is now running at `http://localhost:8787`. Leave `OPENAI_API_KEY` empty — you don't need it in this mode.

### Step 2: Install cc-connect

```bash
npm install -g cc-connect
```

### Step 3: Connect Claude Code to the app

```bash
cc-connect start --url http://localhost:8787
```

cc-connect will start a Claude Code CLI session and bridge messages between the CLI and the companion app. Messages you send in the app's chat will be forwarded to Claude Code, and Claude Code's responses will appear in the app.

### Step 4: Access from your phone

If the app is running on a remote server or VPS:

1. Set `APP_AUTH_TOKEN` in `.env` for security.
2. Put it behind HTTPS (nginx, Caddy, or Cloudflare Tunnel).
3. Open the HTTPS URL on your phone — it's a PWA, so you can add it to your home screen.

## FAQ

### Can I use Pro subscription instead of API key?

Yes. cc-connect uses Claude Code CLI, which runs on your Pro/Max/Team subscription. No separate API key needed.

### Does this work with other AI CLIs?

cc-connect supports Claude Code, Cursor, and Gemini CLI. Check the [cc-connect docs](https://github.com/chenhg5/cc-connect) for the full list.

### What about the OpenAI-compatible mode?

It still works. If you set `OPENAI_API_KEY` in `.env`, the app uses that for standalone operation. When cc-connect is active, it takes over as the AI backend.

### Does `/forge` rotate my Claude Code session?

Only if you configure an external forge adapter.

By default, `/forge` is companion-local history cleanup: it cleans the app's stored chat/group rows, preserves normal user/assistant text, removes tool/thinking/progress noise, and records a new local history id. In this mode it does not create a real Claude Code / cc-connect session, call `claude --resume`, start or stop Claude Code, edit Claude Code transcript JSONL files, copy turns into a new Claude Code session, or delete cc-connect bridge processes.

To make `/forge` perform real session work, set `FORGE_ADAPTER_URL` in the companion app. The app will POST the cleaned history plan to that adapter first, and will only commit its local history segment after the adapter succeeds. The adapter is responsible for cc-connect/Claude Code behavior such as stopping an old process, creating or switching a real session, retaining transcript context, and returning a short JSON result. Without that adapter implementation, there is no real session rotation.

For example, a private adapter can expose:

```bash
FORGE_ADAPTER_URL=http://127.0.0.1:9876/forge
FORGE_ADAPTER_TOKEN=change-me
```

The request includes `operation`, `previous_local_history_id`, `new_local_history_id`, `settings`, `stats`, and cleaned `chat` / `group` message arrays. A non-2xx response or `{ "ok": false }` aborts the companion-local forge.

### Can the app show remaining Claude Code quota?

Yes, with an external quota adapter. The companion app itself cannot infer Claude Code subscription usage, API-provider quota, or cc-connect limits. Set `QUOTA_ADAPTER_URL` to point at a small private service that runs your preferred quota check, for example a wrapper around `ccusage` or a cc-connect management helper:

```bash
QUOTA_ADAPTER_URL=http://127.0.0.1:9876/quota
QUOTA_ADAPTER_TOKEN=change-me
```

Then use `/quota` in the Console tab. The app POSTs `operation`, `requested_at`, `settings`, and current local `session` metadata to the adapter. A typical adapter response can include `provider`, `model`, `remaining`, `used`, `limit`, `resets_at`, and `window`; the app records those fields as a console event.

### I was using tmux to pipe Claude CLI — should I switch?

Yes. The tmux approach creates a conflict: `server.js` can't access thinking blocks from the CLI output, and switching to direct API mode loses MCP tools. cc-connect solves both by acting as a proper bridge layer.
